## 实现说明

代码位于 `src/main/java/com/example/gsb/pbft/`：

| 类 | 职责 |
|----|------|
| `Cluster` | 集群装配：创建 `n` 个节点、提交客户端请求、聚合统计 |
| `Node` | PBFT 三阶段状态机 + 视图更换逻辑 |
| `Network` | 内存消息路由：同步投递、节点隔离、消息延迟、故障注入 |
| `Message` / `KeyStore` | 消息与带钥摘要签名（模拟签名校验） |
| `Stats` | 各阶段消息数、去重丢弃数、验签失败数、视图更换次数、达成一致请求数 |

### 三阶段协议

1. **预准备（Pre-Prepare）**：当前视图的主节点（`view % n`）为请求分配序号并广播；
2. **准备（Prepare）**：节点收到与预准备匹配的、来自 **2f 个不同节点** 的准备消息后进入 prepared 状态（同节点重复消息去重丢弃）；
3. **提交（Commit）**：prepared 后广播提交消息，收到 **2f+1 个不同节点** 对同一值的提交消息后达成一致。

安全约束：节点必须自身 prepared 后才能凭提交法定人数提交，防止被提交消息“带跑”而跳过前两个阶段。

### 为什么是 3f+1

设集群共 `n` 个节点，其中最多 `f` 个拜占庭节点。提交法定人数取 `2f+1`：

- **可用性**：`f` 个节点全部故障时，剩余 `n - f` 个诚实节点必须能凑齐法定人数，即 `n - f >= 2f + 1`，得 `n >= 3f + 1`；
- **安全性**：任意两个 `2f+1` 法定人数在 `n = 3f+1` 个节点中至少重叠 `(2f+1)*2 - (3f+1) = f+1` 个节点，其中至少 1 个是诚实节点。诚实节点在同一视图对同一序号只投一次票，因此两个不同的值不可能同时达到法定人数——恶意节点无法制造分裂。

### 视图更换

主节点失效（超时/被隔离）时，节点广播 `VIEW_CHANGE` 指控；任意节点收集到 `2f+1` 张指向同一新视图的选票后切换视图（`view + 1`，主节点轮换为 `view % n`）。新主节点广播 `NEW_VIEW` 并为所有**未完成**的请求重新发起预准备，已提交的结果保留，保证更换视图后请求仍能继续达成一致。

### 节点数不足 3f+1 的后果

以 `n = 3, f = 1` 为例（`3 < 3*1+1`）：

- 提交法定人数 `2f+1 = 3` 等于全部节点数，**任意 1 个节点故障即永久无法提交**（丧失可用性）；
- 视图更换的 `2f+1` 选票同样凑不齐，主节点失效后系统彻底停摆；
- 若为了恢复可用性把法定人数降为简单多数（如 2），则 1 个拜占庭节点可以向不同诚实节点投矛盾票，使两个不同的值各自“达标”（丧失安全性）。

对应测试见 `InsufficientNodesTest`：3 节点集群隔离 1 个节点后，准备阶段虽能完成，但提交与视图更换均无法达成；对照组 `n = 4 = 3f+1` 在同样 1 节点失效时正常达成一致。

### 恶意行为模拟与签名校验

- **伪造消息**：不知道目标节点密钥，只能猜密钥签名，摘要校验失败被丢弃；
- **延迟响应**：`Network.holdFrom` 积压该节点全部消息，其余 `2f+1` 个节点照常达成一致，恢复后慢节点补齐状态；
- **矛盾消息**：恶意节点用真密钥对不同值投票，但同一发送者的重复投票被去重，矛盾值凑不齐法定人数；
- **签名校验**：`签名 = digest(密钥, 类型, 视图, 序号, 值, 发送者)`，任何篡改内容或冒名的消息验签失败即丢弃并计入统计。

## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的多节点里可能存在返回错误结果的恶意或故障节点，简单多数决不够用。请从零实现一个拜占庭容错投票组件（PBFT 简化版）。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ），节点与消息用内存对象模拟。要求：1) 支持预准备、准备、提交三阶段，节点数为 3f+1 时可容忍 f 个错误节点，需说明该公式来源；2) 准备阶段要求收到 2f 个来自不同节点的准备消息才进入提交，重复消息要去重；3) 支持视图更换：主节点失效时选出新主节点，更换后未完成的请求要能继续达成一致；4) 恶意节点行为模拟：伪造消息、延迟响应、发出矛盾消息三类都要能构造并验证系统仍能达成一致；5) 支持消息签名校验（用简化的摘要校验模拟），签名不匹配的消息必须被丢弃；6) 支持统计：各阶段消息数、去重丢弃数、视图更换次数与达成一致的请求数；7) 说明节点数不足 3f+1 时的后果，并给出测试证明无法容忍；8) 测试覆盖三阶段达成、重复消息去重、三类恶意行为、视图更换、签名校验与节点数不足；`mvn -q verify` 一条命令跑通。
